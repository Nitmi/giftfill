# GiftFill v0.3.0 数据与操作边界

## 银行卡交给浏览器或密码管理器

已删除银行卡保存、解锁、资料绑定与自动填写模块。升级后的后台启动或打开界面会移除旧版 `giftfill.payment-vault.v1` 加密对象，不解密或导出其中内容。原有联系资料存储键不变。

扩展不读取、记录、修改卡号、持卡人姓名、有效期与 CVV；识别联系字段时排除 `cc-*` 自动填写标记。不会访问浏览器或密码管理器的已存卡库。自动测试用会抛错的卡片字段读写器验证这些字段没有被访问。

## 联系资料

金额、收发件邮箱、电话和实际账单地址在 `chrome.storage.local` 本地明文保存。普通 JSON 备份也包含这些资料。存储设为 TRUSTED_CONTEXTS，内容脚本只能收到本次选定资料；没有服务端、云同步或遥测。

点击「一键开始」即使用所选资料填写 Apple 页面，并可能通过 Add to Bag 向 Apple 提交这些礼品卡资料。已有联系与账单字段按所选资料替换，空字段不填写。

## 自动步骤与停止边界

由用户点击启动，不保存后台任务。流程固定作用于启动时的目标标签页。面板关闭或停止会取消后续步骤，已发出的操作可能已经完成，已填内容保留。

导航按钮仅允许 Add to Bag、Check Out、Continue as Guest。结账页只选择 Apple 已知信用卡选项来展开账单表单，没有泛化的 Continue、Pay 或 Place Order 点击规则。付款页 Continue、订单核对、最终购买、登录、OTP、CAPTCHA 与支付验证均由用户自行处理。

购物袋须仅有一张 Apple Gift Card by Email，数量为 1；商品金额、总额、收发件姓名邮箱均须与资料一致才继续。额外商品、未知信息、金额不一致、异常跳转、验证或超时会停止。页面跳转导致消息断开时不重新发送可能成功的点击，每份文档记录已经执行的运行标识。

## 网页权限

只匹配美区购买路线的 HTTPS Apple 主机，拒绝伪域名、URL 用户凭证和非默认端口。没有 iframe 注入，不申请 cookies、debugger、网络拦截或广泛 tabs 权限。苹果主机权限的浏览器提示可能比内容脚本路径范围更宽。

资料仅存本地不代表能抵御本机恶意软件、被篡改的扩展或已受控制的浏览器。填写后的联系资料可由 Apple 页面读取。字段校验通过不代表 Apple 最终地址审核、风控或银行授权一定通过。
